# 자율주행 확장 구조

이 문서는 향후 기능을 연결할 자리와 현재 사용 가능 여부를 구분합니다. 현재 동작하는 주행은 수동 제어뿐이며, 자율주행 컨트롤러는 주행 명령을 만들지 않습니다.

## 계층

```text
웹 UI
  └─ 수동 입력 / 향후 자율주행 모드 선택
       └─ AutonomyController 입력·상태 인터페이스
            └─ MotionCommand (방향, PWM, 조향)
                 └─ ControlService (검증, watchdog, stop 우선 처리)
                      └─ PiCarXAdapter 또는 MockAdapter
```

자율주행 알고리즘은 PiCar-X 메서드를 직접 호출하지 않습니다. 구현되더라도 센서 입력을 공통 `MotionCommand` 후보로 변환하고, 실제 적용은 기존 `ControlService`의 PWM·조향 제한, 명령 만료, 정지 우선 정책을 통과해야 합니다.

## 컨트롤러 상태

`GET /api/autonomy/modes`는 수동 주행과 향후 모드의 현재 상태를 반환합니다. 현재 `manual`만 사용 가능하고 다음 기능은 준비 자리만 있으며 `unavailable` 상태입니다.

- 라인 추적: 확인된 그레이스케일 센서 입력 필요
- 장애물 회피: 전방 거리 센서 입력 필요
- 객체 추적 및 카메라 추적: 실제 영상 스트림과 인식 결과 입력 필요
- 통합 자율주행: 안전 검증된 하위 컨트롤러 필요

구현되지 않은 모드의 `POST /api/autonomy/start` 요청은 HTTP 409로 거절됩니다. 카메라 스트림, GPS, 엔코더 속도, IMU 기능은 현재 없는 것으로 반환합니다. 카메라 서보는 영상 스트림과 별도 기능입니다.

## 확인된 하드웨어 입력

PiCar-X 어댑터는 설치된 라이브러리의 함수 존재 여부를 확인한 뒤 사용합니다. 확인된 센서는 `get_distance()`, `get_grayscale_data()`, `get_cliff_status(grayscale)`입니다. 실제 센서 값이 없거나 API가 없으면 `null` 또는 사용할 수 없음으로 표현하며 가상 데이터를 실물 상태로 섞지 않습니다.

`GET /api/autonomy/capabilities`는 센서 API, 모터·조향·카메라 서보 가용성과 아직 지원하지 않는 스트림·GPS·속도 센서를 각각 반환합니다. 모의 모드의 가상 센서는 하드웨어 capability로 표시하지 않습니다.

## 정지와 오류 기록

알고리즘 오류, 센서 읽기 오류, stop 실패, watchdog 오류는 `backend/data/events.jsonl`에 JSONL로 기록됩니다. `GET /api/logs?limit=100`은 최근 이벤트를 반환합니다. 로그 파일이 기록되지 않아도 주행 제어와 정지 처리가 차단되지 않습니다.

자율주행 구현을 시작할 때는 먼저 입력 센서의 신선도·오류 상태를 검증하고, 제한된 명령 후보를 생성한 뒤 공통 안전 계층에서만 실행해야 합니다. 위험 입력, 오래된 입력, 제어기 timeout, 사용자 긴급 정지는 모든 자율주행 모드보다 stop이 우선합니다.
