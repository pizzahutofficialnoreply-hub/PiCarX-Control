# 방지턱 충격 실험 기능

창의력산출물 탐구 "질량과 속도에 따른 관성의 영향 분석 – 자동차가 방지턱 통과 시 충격을 최소화하는 속도"를 위한 기능입니다. 앱의 **실험 관리** 화면에서 조건 입력 → 자동 측정 주행 → 시행 그래프 확인 → 조건별 집계 → 관계식 도출까지 진행합니다.

## 화면 구성

**실험 관리** 화면은 하위 탭 다섯 개로 나뉩니다.

| 탭 | 하는 일 |
|---|---|
| 측정·분석 | 조건 입력, 자동·반복 측정, 실험 진행표, 시행 그래프와 앞·뒤 바퀴 피크 확인·직접 지정, 선택 삭제, 조건별 평균, 관계식 후보 비교, 자동 해석 문장 |
| 식 검증 | 본 실험으로 만든 관계식으로 새 조건(실험하지 않은 질량 등)의 충격을 예측하고, 그 조건에서 측정해 오차율 확인 |
| 라인 추종 | 바닥 테이프를 그레이스케일 센서로 따라가기(보정, 시험 주행, 측정 직진에 사용) |
| 점검·데이터 | 실제 데이터 입력 확인, 배터리, 전진·후진 출력 대칭 점검과 방향별 출력 배율, 백업 ZIP, 초기화·휴지통, 측정 전 점검표 |
| 해석 가이드 | 그래프·CSV 읽는 법, 앞·뒤 바퀴 구분 규칙, 관계식 다루는 법, 선행 연구(사람 허용 가속도), 실제 도로 환산 |

## 주행 조작 (PC 키보드)

주행 화면에서 마우스·키보드가 있는 PC일 때만 켜집니다(휴대폰·태블릿은 기존 버튼·조이스틱). 한글 입력 상태에서도 동작합니다.

| 키 | 동작 |
|---|---|
| W / S | 누르는 동안 전진 / 후진 (떼면 정지) |
| A / D | 누르는 동안 왼쪽 / 오른쪽 조향 |
| Space | 즉시 정지 |
| Q / E | 출력 −5 / +5 |
| ← → ↑ ↓ | 카메라를 3°씩 좌우·상하로 (Shift를 누르면 6°). 주행을 멈추지 않으며 보정값은 바뀌지 않음 |
| C | 카메라 가운데로 |

- 출력 상한은 **100**입니다(이전 60).
- 출발할 때 0부터 0.1초마다 1씩 올리던 방식을 없애고 **설정 출력으로 바로** 보냅니다.
- 주행 화면 왼쪽 아래에 마지막 모터 명령(방향, 핀 듀티)이 보입니다.
- 전진과 후진은 이제 **같은 코드 경로**로 출력을 적용합니다. 그래도 속도가 다르면 *점검·데이터 → 전진·후진 출력 대칭 점검*에서 원인(앱이 보낸 듀티가 같은지, 기계 차이인지)을 확인하고 방향별 배율로 맞춥니다.

## 측정 원리

| 항목 | 방법 |
|---|---|
| 수직 가속도 | MPU-6050, 약 1 kHz 목표, DLPF 184 Hz, ±8 g. 정지 보정 자세 기준으로 정지 = 1 g, 공중 = 약 0 g |
| 통과 속도 | 앞바퀴·뒷바퀴가 방지턱에 닿을 때 생기는 두 피크의 시간 간격 Δt와 축간거리 L로 `v = L / Δt` |
| 지면 이탈(점프) | 수직 가속도가 지면 이탈 기준(기본 0.2 g) 미만으로 5 ms 이상 유지된 구간 |
| 착지 피크 | 공중 구간 직후 30 ms 안의 피크. 바퀴 피크 짝짓기에서 제외해 속도 오계산을 막고, 착지 충격은 따로 기록 |
| 충격력 | `F = m · g · a_peak` (N). 증가분은 `m · g · Δa` |
| 무차원수 | `Π = v² / (g · R_eff)`, `R_eff = R + r`, `R = (w²/4 + h²) / (2h)`. Π = 1이 이론상 점프 경계 |
| 조건별 평균 | 같은 방지턱·질량·출력에서 3회 이상이면 최댓값·최솟값을 하나씩 빼고 평균 |
| 관계식 | 조건 평균에 대해 `log Δa = log k₀ + n log v + p log m` 최소제곱. `v_max = ((a_lim − 1) / (k₀ m^p))^(1/n)` |

## 사용 순서

1. 백엔드를 실제 하드웨어 모드로 실행하고(`PICARX_MODE=hardware`), 앱 설정에서 Raspberry Pi 주소로 연결합니다.
2. **센서** 화면에서 차량을 평평한 곳에 두고 *정지 상태 보정*을 누릅니다. 실제 표본 속도(Hz)가 500 이상인지 확인합니다.
3. **실험 관리 → 차량·분석 설정**에 축간거리, 바퀴 반지름, 기본 질량, 방지턱 높이·폭, 허용 최대 가속도를 입력하고 저장합니다.
4. **실험 조건**에서 방지턱, 추가 질량(0 / 150 / 300 g), 출력 방식과 출력값, 회차를 정하고 *자동 측정 주행*을 누릅니다.
   차는 정지 기록(기본 1 s) → 직진(기본 2.5 s) → 정지 후 기록(0.6 s) 순으로 움직이고, 끝나면 자동으로 분석·저장됩니다.
5. 시행 그래프에서 앞·뒤 바퀴 피크가 올바르게 잡혔는지 확인합니다. 이상한 시행은 *집계에서 제외*합니다.
6. 조건별 표, 그래프 1(속도–Δa), 그래프 2(Π–a_peak), 회귀식과 v_max 예측을 확인합니다. 그래프는 PNG(1920×1080)·SVG로, 표는 CSV로 저장합니다.

축간거리나 검출 기준을 나중에 바꾸면 *저장 후 전체 재분석*으로 저장된 원자료를 다시 계산할 수 있습니다.

## 반복 측정 (직진 → 후진 복귀)

*반복 측정 시작*을 누르면 아래를 정해진 횟수만큼 반복하고, 회차마다 별도 시행으로 저장합니다(회차 번호 자동 증가).

1. 정지 기록(기본 1 s) – 이때 자이로 영점을 잡고 방향을 0으로 둡니다.
2. 직진 측정(기본 2.5 s) – 기록·분석·저장
3. 정지 후 기록(기본 0.6 s)
4. 출발선으로 후진 복귀 – 직진과 같은 시간 × *복귀 시간 배율*, 출력은 *복귀 출력*(빈칸이면 측정 출력)
5. 회차 사이 대기(기본 1.5 s) – 차체 진동이 가라앉도록

후진은 시간 기준이라 출발선과 조금 어긋날 수 있습니다. 출발 위치에서 차 앞쪽 그레이스케일 센서 아래에 테이프를 가로로 붙이고 라인 보정을 한 뒤 *출발선 테이프에서 멈추기*를 켜면, 후진 중 센서가 테이프를 보면 멈춥니다(계획 시간의 40% 이후부터 감지, 못 찾으면 1.6배 시간에서 정지). 후진 복귀 구간은 기록·분석하지 않습니다. 덜 돌아오면 배율을 늘리고, 더 가면 줄이세요. 정지를 누르면 즉시 멈추고 남은 반복을 취소합니다.

### 후진으로 측정하기

조건의 *측정 방향*을 '후진'으로 고르면 후진하며 방지턱을 넘고, 복귀는 전진으로 합니다. PiCar-X는 뒷바퀴 구동이라 후진하면 구동 바퀴가 먼저 턱을 오르므로 전진보다 턱 앞 감속이 적을 수 있습니다. 전진과 후진 결과는 섞지 않습니다: 분석·관계식·진행표는 마지막으로 고른 방향(`analysis_direction`)의 측정만 씁니다. 후진 측정에서는 테이프 센서(차 앞쪽)를 쓸 수 없어 자이로로 방향을 유지합니다. 속도 계산(v = L/Δt)과 기울기 판정은 방향과 상관없이 같습니다.

### 방지턱을 넘으면 자동 정지

속도(PWM)마다 같은 시간 동안 가는 거리가 다르므로, 기본으로 **방지턱을 다 넘으면 자동으로 멈춥니다**(설정 `stop_after_bump`, 다 넘은 뒤 0.3 s 더 주행). 자이로로 앞뒤 기울기를 실시간 적분해 '+(앞바퀴 오름) → −(앞바퀴 내림 또는 뒷바퀴 오름) → 수평 0.12 s(뒷바퀴 내림)' 순서를 확인합니다. 이 경우 '주행 시간'은 최대 시간이 되므로 가장 느린 PWM도 다 넘을 만큼 넉넉히(예: 5 s) 두세요. 못 알아내면 최대 시간까지 달립니다. 후진 복귀는 실제로 앞으로 달린 시간 × 복귀 배율만큼 합니다.

### 일정한 출력으로 주행

관계식이 없을 때(지금 단계)는 측정 주행 동안 **모터 출력을 처음부터 끝까지 한 값으로 고정**합니다. 예전에는 50 ms마다 조향이 바뀔 때 라이브러리 `forward()`가 조향각에 따라 한쪽 바퀴 출력을 줄여(`power_scale`) 차가 '멈칫'했습니다. 이제 측정 주행은 두 바퀴에 같은 출력을 한 번만 쓰고(`set_motor_speed`), 직진 보정은 조향 서보만 움직입니다. 시행마다 *주행 기록*(시각·출력·조향·방향)을 저장하므로 시행 화면에서 "모터 출력: 처음부터 끝까지 PWM 90로 고정"처럼 확인할 수 있습니다.

### 자이로 직진 보정

MPU-6050의 수직축 자이로를 적분해 차의 방향(yaw)을 추적하고 조향 서보로 되돌립니다.

- 조향 = 기본 조향(학습값) + *직진 보정 세기* × 방향 오차 + *쌓인 오차 보정* × 오차의 누적(최대 ±12°)
- *쌓인 오차 보정*(적분, 기본 0.8)은 '계속 한쪽으로 조금씩 휘는' 차를 잡습니다. 좌우로 흔들리면 세기를 낮추세요.
- *직진 습관 자동 학습*(기본 켬): 매 회차 뒷부분의 평균 조향을 기억해(지수 평균) 다음 회차는 처음부터 그만큼 미리 꺾고 출발합니다. 전진·후진을 따로 학습하며, 바퀴 정렬을 바꾸면 *잊기*로 0으로 돌리세요. 다른 설정을 저장해도 학습값은 지워지지 않습니다.
- 와인드업 방지: 조향이 한계(±12°)에 붙어 있거나 목표를 지나치면 적분을 쌓지 않거나 크게 줄여, 한쪽으로 계속 꺾인 채 남지 않습니다.
- 보정 방향 자동 판정: 센서 장착 방향에 따라 보정이 거꾸로 걸릴 수 있습니다. 오차를 줄이려고 6° 이상 꺾는데도 0.6초 동안 오차가 3° 넘게 커지면 그 자리에서 방향을 뒤집고, 다음 측정부터 뒤집힌 방향(`heading_sign`)을 씁니다(학습값은 0으로).
- 학습값은 최대 ±5°이고, 조향이 한계에 오래 붙어 있던 회차는 배우지 않습니다.
- 자이로는 '출발한 뒤 틀어진 각도'만 압니다. **처음 놓은 방향이 비뚤면 비뚠 방향으로 곧게 갑니다.** 출발선에 자나 테이프로 방향 표시를 해 두고 놓으세요. 정확히 선을 따라야 하면 라인 추종을 쓰세요.

## 허용 최대 수직 가속도 기준

분석 카드의 *사람이 견딜 수 있는 충격 기준*에서 고릅니다. 값은 '평소(정지 1 g)보다 더 받은 가속도' Δa이고, 내부 기준 a_lim = 1 + Δa입니다.

| 선택 | Δa | 근거 |
|---|---|---|
| **TRL 614 (기본)** | 0.7 g | Kennedy 외(2004, 영국 TRL): 실제 차량 5종·더미로 방지턱을 측정한 대규모 연구. 승용차 탑승자 수용 한계로 가장 널리 인용 |
| Watts (1973) | 0.9 g | TRRL LR597: 피험자 불편 점수 |
| Kjemtrup (0.4 g) | 0.4 g | 구급차·환자 기준(Kyrollos 외 2020 인용) |
| Kjemtrup (0.2 g) | 0.2 g | 매우 엄격한 기준 |
| 직접 입력 | — | 원하는 값 |
| 바퀴가 처음 뜬 조건 | — | 이 실험에서 점프가 처음 나타난 조건의 평균 최대 가속도 |

기준을 넘은 충격은 **빨간색**으로 강조됩니다: 시행 그래프의 빨간 기준선과 빨간 피크 점('기준 초과'), 시행 목록·조건 표의 빨간 줄과 '기준 초과' 표시, 그래프 1의 빨간 테두리 점. 질량마다 v_max(기준을 넘지 않는 최대 속도)도 표로 보여 줍니다.

## 시행 보기

- **한 회씩**: ◀ ▶ 버튼이나 키보드 ← → 로 넘깁니다. *같은 조건만*/*전체 시행*으로 넘기는 범위를 고릅니다.
- **겹쳐 보기**: 최근 40회까지 앞바퀴가 닿은 순간(0초)에 맞춰 한 그래프에 겹칩니다. 색 = 출력, 선 모양 = 질량, 굵은 선 = 지금 고른 회차. 아래 표에서 줄을 누르면 그 회차를 한 회씩 보기로 엽니다.
- 피크 후보('후보 1, 2, …')는 *앞·뒤 바퀴 피크 확인·직접 고르기*를 열었을 때만 그래프에 표시됩니다. 후보 번호로 고르거나, *그래프에서 앞바퀴/뒷바퀴 찍기*를 누른 뒤 그래프를 직접 클릭해 고를 수 있습니다(클릭한 곳 ±15 ms 안의 최댓값으로 맞춤). 직접 지정하면 자동으로 골랐던 위치가 회색 점선 원으로 남고, *자동으로 되돌리기*로 언제든 원래대로 돌아갑니다.
- 모든 그래프는 마우스를 올리면 툴팁으로 값(시각·가속도·조건·속도 등)을 보여 줍니다.

## 내보내기

- **핵심 요약 CSV**: 방지턱·질량·출력(PWM)·회차 순으로 정렬한 표(통과 속도, 앞·뒤 간격, 최대 충격, Δa, 기준 초과, 바퀴 뜸, 바퀴 찾은 방법, 표본 속도, 확인할 점) + 조건별 평균 + 자동 해석.
- **원자료 ZIP**: 체크한 회차(없으면 전체)의 원자료 CSV를 한 파일로. 파일 이름에 방지턱·질량·출력·회차가 들어갑니다.
- 시행 CSV(전체 항목), 조건별 CSV는 그대로입니다.

## 분석 옵션 (시행 결과 위)

- **진동 거르기**: 끔 / 30 / 20(추천) / 15 / 10 Hz. 위아래 가속도에 2차 버터워스 저역 통과 필터를 앞뒤로 한 번씩 걸어(위상 지연 없음) 차체·센서가 빠르게 출렁이는 떨림을 지웁니다. 그래프에는 거른 선(파랑)과 원래 기록(연한 회색)이 함께 나옵니다. **피크는 거의 깎지 않습니다**: 피크를 찾고 앞·뒤 바퀴 시각(속도)을 정하는 데는 거른 신호를 쓰고, 피크 높이(최대 충격·앞/뒤 바퀴 g)는 그 시각 ±10 ms 안의 거르기 전 원래 값으로 되돌립니다. 그래프의 파란 선도 충격 봉우리 앞뒤 10 ms는 원래 기록을 그대로 보여 줍니다. 거르기를 켜면 '최소 충격' 고정 기준을 절반으로 낮춥니다(진동 기준은 그대로).
- **방지턱 감지 민감도**: 엄격(진동 σ의 6배, 다른 진동보다 1.5배) / 보통(4.5배, 1.3배, 기본) / 민감(3.5배, 1.15배, 최소 충격 ×0.6). 민감은 작은 방지턱·느린 속도도 잡지만 평지 오검출 가능성이 커지니 겹쳐 보기로 확인하세요.
- 바꾸면 저장된 원자료로 모든 시행을 바로 다시 분석합니다.

가상 시험(28 Hz ±0.3 g 진동 + 0.5 m/s 방지턱): 거르기 없이는 못 찾고, 20 Hz 거르기로 찾음(속도 오차 5% 이내). 평지는 모든 조합에서 '못 찾음'.

## 이론·예측·제어 탭

**목표 1 · 예측식**: 측정·분석 탭에서 고른 관계식(또는 직접 만든 식)을 F = m·a 꼴로 보여 줍니다.
`Δa = f(v, m)`, `a_peak = 1 + Δa`, `F = m·g·(1 + Δa)`, 그리고 `v = a + b·P (+ c·m)`(출력 → 속도, 질량 2단계 이상이면 질량 항 포함).
계산기에 총질량과 PWM(또는 m/s)을 넣으면 v → Δa → a_peak → F 순서로 계산하고, 거꾸로 목표 a_peak(또는 F)를 넣으면 v_max와 그 속도를 내는 PWM을 구합니다. 측정 범위 밖이면 외삽 경고를 띄웁니다.

**이론식 ①②③ 분석**
- ① F = m·a: 출력별로 질량–충격력을 그리고, 질량이 100 g 늘 때 Δa가 몇 % 바뀌는지 계산합니다(0에 가까우면 F ∝ m).
- ② 충격량: 각 회차의 앞·뒤 바퀴 충격 펄스 넓이 `Δv_z = g·∫(a−1)dt`(펄스는 피크 높이 10%까지, 최대 ±60 ms)로 `I = m·Δv_z`를 구하고, 운동량 m·v와 비교합니다. 이론값은 바퀴 중심이 원호에 오를 때 꺾이는 각 α로 `I = m·v·sin α`, `sin α = √((R+r)² − (R−h+r)²)/(R+r)`. 펄스 길이 Δt와 속도의 로그 기울기(Δt ∝ v^−q)로 `F ∝ v^(1+q)`를 예상해 관계식의 n과 비교합니다.
- ③ 원운동: 앞바퀴 피크~뒷바퀴 피크 사이 최솟값을 `a = 1 − Π`(Π = v²/(g·R_eff))와 비교하고, Π = 1(수직항력 0, 점프)을 표시합니다.

**직접 만드는 관계식**: 식을 글자로 쓰면(예: `k*v^n*m^p`, `c*v^2/(g*R)`, `a*v + b*v^2`, `m*g*(1+k*v^n*m^p)`) 레벤버그–마쿼트 최소제곱으로 매개변수를 맞추고 R², RMSE, 교차검증 RMSE, AIC, 95% 범위를 보여 줍니다. 변수 v, m(kg), P(출력), g, R(R+r), h, w, r, L, s(sin α)를 쓸 수 있고 나머지 이름은 매개변수입니다. 맞출 값은 Δa, a_peak, F, F_dyn, 충격량 I, 펄스 Δt. 저장하면 계산기에서 고를 수 있습니다(브라우저에 저장). 식 만드는 요령은 화면의 '팁'에 있습니다.

**목표 2 · 방지턱 앞 감속 제어**: 고른 관계식으로 v_max(m)를 구해 `v* = v_max × 여유율`, 속도식을 거꾸로 풀어 출력*를 정한 뒤, 시작 조건(출발 후 시간 / 벽까지 거리(초음파) / 바닥 감속 테이프)에 출력을 줄입니다. 결과는 '식 검증' 시행으로 저장되어 관계식에는 섞이지 않고, 실제 통과 속도·최대 충격과 기준 통과 여부를 표와 그래프로 봅니다. 모터 속도가 바뀌는 데 0.2~0.4초 걸리므로 감속은 방지턱보다 충분히 앞에서 시작해야 합니다.

**초음파 거리·속력**: 측정 주행 중 앞쪽 초음파 센서를 초당 5~40번(기본 20) 별도 스레드로 읽어 MPU 기록과 같은 시간축에 저장합니다. 이웃 점 직선(테일–센)에서 크게 벗어난 튀는 값을 빼고, 앞뒤 0.15초 국소 직선의 기울기로 속력을 구합니다. 방지턱 직전/통과 중/최저 속력, 감소율, 속력이 8% 넘게 줄었다가 회복하는 '골'(초음파로 찾은 방지턱)과 MPU 앞바퀴 시각의 차이, 앞바퀴 충격 때 벽까지 거리를 계산합니다. 벽 앞 자동 정지(cm)를 켜면 그 거리에서 멈춥니다. PiCar-X에는 라이다가 없고, 카메라 한 대로는 거리를 바로 알 수 없어 쓰지 않습니다.

## 이상치 처리 방식

분석 및 관계식 위에서 고릅니다(설정 `outlier_method`).
- `trim`: 3회 이상이면 최댓값·최솟값 하나씩 제외(계획서 원래 규칙)
- `sigma2`: 평균 ± 2×표본표준편차(AVERAGE, STDEV.S) 밖 제외. 이상치가 s도 키우므로 n ≤ 5면 거의 제외되지 않음(최대 z = (n−1)/√n)
- `iqr`: Q1 − 1.5·IQR 미만 또는 Q3 + 1.5·IQR 초과 제외(QUARTILE.INC)
- `none`: 모두 사용

조건별 표에 표준편차와 제외 기준 범위가 함께 나옵니다.

## 그래프 보기 설정

한 회씩 보기와 겹쳐 보기는 같은 '방지턱 부분 / 전체 기록' 선택을 쓰고, 마지막 선택을 기억합니다. 방지턱 부분은 둘 다 앞바퀴 −0.15초 ~ 뒷바퀴 +0.3초(최소 +0.45초)입니다. 한 회씩 보기는 기본으로 앞바퀴 = 0초 시간축이라 겹쳐 보기와 눈금이 같고, '기록 시작 = 0초'로 바꿀 수 있습니다. 겹쳐 보기도 진동 거르기(피크 보존)와 같은 조건 회차 맞춤을 똑같이 적용하며, 거르기 전 원래 기록으로 볼 수 있습니다.
**피크 자동 동기화**를 켜면 기준 회차(지금 고른 회차)와 앞·뒤 바퀴 간격이 15% 안, 앞바퀴 충격 크기가 0.67~1.5배이고 파형 상관이 0.8 이상인 회차만 ±15 ms 안에서 옮겨 봉우리를 맞춥니다. 옮긴 양과 이유는 표에 나옵니다.

숫자 칸은 누르면 전체가 선택되어 바로 새 값을 칠 수 있고, 지우는 동안 기본값이 끼어들지 않습니다. 보기 방식과 입력값은 브라우저에 기억됩니다.

## 관계식 항목 설명

관계식이 정해지면 분석 카드 아래에 식의 각 기호(Δa, v, m), 매개변수(k₀, n, p 또는 a, b, c)의 뜻과 지금 값의 해석(예: "속도 2배 → 충격 2ⁿ배", 신뢰구간이 1·2·0을 포함하는지), 맞춤 지표(R², RMSE, 교차검증 RMSE, AIC), v_max의 뜻을 보여 줍니다.

## 차 기울기로 앞·뒤 바퀴 찾기 (1순위)

자이로로 앞뒤 기울기(피치)를 적분하면 앞바퀴가 턱에 오를 때 앞이 들리고(+θ ≈ asin(h/L)), 뒷바퀴가 오를 때 다시 수평(넓은 방지턱) 또는 뒤가 들림(좁은 방지턱)이 됩니다. 기울기가 최대치의 25%를 넘는/내려가는 순간을 각 바퀴의 '오름' 시각으로 잡고, ±80 ms 안의 가장 큰 충격 피크에 맞춥니다(`pair_source = pitch`). 그래서 **방지턱 폭(주행 방향 길이)을 정확히 입력해야** 넓은지 좁은지를 맞게 판단합니다. 검증: PWM 55 회차에서 기울기 방법 0.24 m/s, 같은 회차 영상(30 fps, 바퀴 지름 기준) 약 0.23 m/s.

## 바퀴마다 두 번 충격(오름·내림)

방지턱에 폭이 있으면 바퀴마다 올라갈 때와 내려올 때 두 번 충격이 납니다(총 4개). 분석은 먼저 '앞 오름 → 앞 내림 → 뒤 오름 → 뒤 내림'(폭이 축간거리보다 넓으면 앞 내림과 뒤 오름 순서가 바뀜) 규칙에 맞는 4개 묶음을 찾습니다. 앞 오름→뒤 오름 간격과 앞 내림→뒤 내림 간격이 같아야 하고(±15%), 두 바퀴가 방지턱을 지나는 시간도 같아야 합니다(±35%). 속도는 두 간격의 평균으로 계산합니다(`pair_source = pattern`). 자이로로 적분한 앞뒤 기울기(앞바퀴만 턱 위면 +θ, 뒷바퀴만이면 −θ, θ = asin(h/L))도 점수에 반영합니다.

같은 점수로 속도가 20% 넘게 다른 해석이 가능하면 '앞·뒤 바퀴 구분이 애매함'과 속도 후보를 표시하고 기존 방식으로 계산합니다. 폭이 축간거리와 비슷한 방지턱(예: 폭 60 mm, 축간거리 95 mm)에서 잘 생기므로, 아주 좁은 둥근 막대(폭 ≤ 15 mm, 충격이 바퀴당 하나로 합쳐짐)나 아주 넓은 방지턱(≥ 250 mm, 앞·뒤 오름이 먼저 나란히 나옴)을 쓰면 확실해집니다. 처음 한 번은 영상(슬로모션, 바닥에 자)으로 속도를 재서 맞는 해석인지 확인하세요.

## 표본 속도

MPU-6050은 I2C로 읽습니다. 라즈베리파이 기본 I2C 속도(100 kHz)에서는 한 번 읽는 데 약 1.6 ms가 걸려 초당 약 450회가 한계이고, 웹 서버·카메라가 CPU를 쓰면 5~18 ms씩 빠지기도 합니다. 몇 ms짜리 충격을 놓치지 않으려면 `/boot/firmware/config.txt`에 `dtparam=i2c_arm_baudrate=400000`을 넣고 재부팅하세요(초당 약 1000회). 측정 중에는 카메라 스트림을 자동으로 멈춥니다.

## 평지 오검출 막기

진동만 있는 평지에서도 작은 봉우리 두 개를 앞·뒤 바퀴로 잡던 문제를 막기 위해:

1. 주행 중 진동 크기(σ, 중앙값 절대편차로 추정)를 재고, 후보 기준을 max(설정값, k·σ)로 올립니다(k는 감지 민감도: 6 / 4.5 / 3.5).
2. 고른 앞·뒤 바퀴 피크 중 더 큰 쪽이 나머지 봉우리보다 뚜렷이(1.5 / 1.3 / 1.15배 이상) 커야 방지턱으로 인정합니다(약한 쪽은 후보 기준만 넘으면 됨). 같은 조건 반복 회차의 앞·뒤 간격 중앙값에서 30% 넘게 벗어난 회차는 그 간격에 맞는 후보 쌍으로 다시 고릅니다.
3. 인정되지 않으면 '방지턱 못 찾음'으로 표시하고 속도를 계산하지 않으며 집계에서 자동으로 뺍니다. 피크를 직접 고르면 다시 포함됩니다.

가짜 차 시험: 방지턱 있음 6회 모두 인정, 평지(`FAKE_BUMP=0`) 2회 모두 '못 찾음'.

## 앞바퀴·뒷바퀴 구분

차는 앞으로 가므로 **먼저 나온 피크가 앞바퀴, 나중 피크가 뒷바퀴**입니다. 피크가 3개 이상이면 ① 공중 구간 직후 30 ms 안의 착지 피크를 빼고 ② 두 피크 간격으로 계산한 속도가 0.03~4 m/s인 쌍 중 ③ 높이 합이 가장 큰 쌍을 고릅니다. 같은 조건 평균보다 속도가 20% 넘게 다르면 경고가 뜨고, *앞·뒤 바퀴 피크 확인·직접 지정*에서 후보를 골라 그 시행만 다시 계산할 수 있습니다(`pair_source = manual`로 기록).

## 관계식 후보 비교

**왜 n을 구하나**: Δa = k·vⁿ에서 n은 '속도를 2배로 하면 충격이 2ⁿ배'라는 뜻입니다(n = 1.6이면 약 3배). n ≈ 1이면 바퀴가 턱에 부딪히는 충돌이, n ≈ 2이면 턱 곡면을 따라 도는 원운동(v²/R)이 충격을 주로 만든다는 해석이 되고, n을 알아야 허용 기준을 넘지 않는 속도 v_max를 계산할 수 있습니다. 질량 지수 p도 같은 방식입니다(p ≈ 0이면 무게와 상관없음).

조건 평균(본 실험만)에 다음 식을 모두 맞춥니다: 거듭제곱(속도·질량), 거듭제곱(속도만), n = 1 고정(충돌 모델), n = 2 고정(원운동 모델), 일차식, 이차식. 각 식의 R², RMSE, **교차검증 RMSE**(한 조건씩 빼고 맞춘 식이 그 조건을 예측한 오차), AIC, 매개변수의 **95% 신뢰구간**을 보여 주고, 기본으로 교차검증 오차가 가장 작은 식을 씁니다(직접 고를 수도 있음). v_max, 그래프 1의 곡선, 식 검증, 자동 해석은 모두 선택한 식으로 계산합니다.

## 식 검증

측정 목적을 *식 검증*으로 저장한 시행은 관계식 계산에서 빠지고, 그 시행의 실측 속도를 식에 넣은 예측 Δa와 실측 Δa를 비교합니다. 식 검증 탭에서 질량과 목표 속도(v_max 또는 직접 입력)를 고르면 '출력 → 속도' 자료로 필요한 출력을 추천하고, 그 조건으로 자동 측정합니다. 평균 절대 오차율 10% 이내면 식이 새 조건을 잘 예측한 것입니다. *예비* 시행은 어디에도 쓰지 않습니다.

## 라인 추종 (바닥 테이프)

밝은 바닥에 검은 테이프(폭 15~20 mm)를 붙이고, 바닥 위·테이프 위에서 한 번씩 보정합니다. 센서 3개의 '테이프에 가까운 정도'로 위치(−1 왼쪽 ~ +1 오른쪽)를 구하고, 조향 = (배율 × 위치 + 감쇠 × 위치 변화율) × 최대 조향각으로 따라갑니다. 초당 50번 계산하며 위치 변화율은 부드럽게 걸러 씁니다. 감쇠(기본 0.25 s)가 없으면 좌우로 점점 크게 흔들려 테이프를 놓칠 수 있습니다. 센서 순서·조향 방향이 반대인 차는, 테이프 쪽으로 세게 꺾는데도 0.35초 동안 테이프가 가운데로 오지 않거나 놓치면 조향 방향을 스스로 뒤집고(2초 회복 시간) 그 값을 저장합니다. 출발선·정지선 테이프는 주행 중 약 2 ms 간격으로 따로 읽어 2번 연속 보이면 멈춥니다. 테이프를 놓치면 0.6초 뒤 멈춥니다. 측정·분석 탭의 *측정 중 조향*을 '바닥 테이프 따라가기'로 바꾸면 측정 직진에도 쓰고, 후진 복귀는 자이로로 방향을 유지합니다.

## 점검·데이터

- **실제 데이터 입력 확인**: 서버 모드, 센서 응답, 보정, 실시간 표본 속도, 마지막 실제 시행의 표본 수와 가속도 범위를 점검합니다. 시행 결과에는 *실제 측정(MPU-6050)* 또는 *합성 데이터* 배지가 붙고, 시행 CSV에 `data_source`로 남습니다.
- **배터리**: robot_hat이 있으면 전압을 보여 주고 각 시행 시작 전압(`battery_v`)을 저장합니다.
- **좌우 바퀴 균형 맞추기**: 직진 보정 없이 조향 0°로 달리며 자이로로 차가 도는 속도(°/s)를 재고, 빠른 쪽 바퀴 출력 배율(`trim_left`/`trim_right`)을 낮춰 0에 맞춥니다(할선법, 최대 5회, ±1.5°/s 이내면 종료). 매 회 같은 시간 반대로 돌아옵니다. 좌우 배율을 쓰면 라이브러리 계산(듀티 = 출력/2 + 50%)을 정수로 자르지 않고 핀에 직접 써서 1% 단위 조정이 가능합니다. 수동 주행(WASD)과 측정 주행 모두에 적용됩니다. 가짜 차(왼쪽 8% 강함) 시험: −27°/s → +0.1°/s(4회).
- **전진·후진 대칭 점검**: 자동으로 맞추기는 느린 쪽 방향의 출력 배율을 먼저 올리고(최대 1.5, 실제 출력 100 이하일 때), 그럴 수 없으면 빠른 쪽을 낮춥니다. 전진 → 정지 → 후진을 같은 출력으로 하며 앱이 보낸 듀티·핀 값과, 가속도 적분 속도를 비교합니다. 줄자로 잰 거리로도 비율을 구할 수 있고, 제안 배율을 적용합니다. 라이브러리 PWM은 출력과 속도가 비례하지 않으므로 0.95~1.05가 될 때까지 2~3번 반복하세요. *자동으로 맞추기*를 누르면 점검 → 제안 배율 적용 → 재점검을 5% 이내가 될 때까지(최대 4번) 자동으로 반복합니다.
- **삭제·초기화**: 시행 목록에서 체크해 여러 개를 지울 수 있습니다(되돌릴 수 없음). *초기화*는 확인 문구 '초기화'를 입력해야 하며, 기록을 휴지통 폴더(`experiments_trash/`)로 옮기므로 *되돌리기*로 복구할 수 있습니다. *백업 ZIP*은 원자료와 설정을 모두 담습니다.
- **실험 진행표**: 방지턱 × 추가 질량 × 출력 계획 대비 완료 횟수를 보여 주고, 칸을 누르면 그 조건이 입력되며 바로 아래에 그 조건의 그래프가 나옵니다. 여러 칸을 누르면 복수 선택(다시 누르면 빠짐), 행(질량)·열(출력) 제목을 누르면 줄 전체를 고릅니다. *평균값 / 모든 값*, *속도(출력)별 / 질량별 비교*를 골라 앞바퀴 기준으로 맞춘 충격 파형과 '통과 속도(또는 총 질량)–Δa' 그래프, 조건별 평균 ± 표준편차 표를 봅니다.

## 선행 연구 (사람이 받아들이는 수직 가속도)

해석 가이드 탭에 요약과 링크가 있습니다. 측정 방식(최대값/RMS, 위치)이 달라 숫자를 섞지 마세요.

| 연구 | 핵심 |
|---|---|
| [Watts (1973), TRRL LR597](https://www.trl.co.uk/uploads/trl/documents/LR597.pdf) | 원호형 혹 15종, 6명 주관 평가. 불편 점수 ∝ 최대 가속도(r ≈ 0.83), 약 0.9 g 초과 시 '불편' |
| [Kennedy 외 (2004), TRL 614](https://trl.co.uk/uploads/trl/documents/TRL614(1).pdf) | 차량 5종·더미 측정. 불편 점수와 최대 가속도 R² = 0.82, 약 0.7 g 이상은 받아들이지 않음 |
| [Kyrollos 외 (2020), CDSR](https://avestia.com/CDSR2020_Proceedings/files/paper/CDSR_156.pdf) | 구급차. Kjemtrup 기준 0.2 g 약간 불편, 0.4 g 상당히 불편 |
| [ISO 2631-1 (Asua 외 2022 인용)](https://arxiv.org/pdf/2501.17664) | RMS 진동 승차감 표(0.315 m/s² 미만 ~ 2 m/s² 초과) – 충격 최대값과 직접 비교 불가 |
| [Aslan 외 (2005), Am J Emerg Med](https://ajemjournal.com/article/S0735-6757(05)00119-1/pdf) | 버스 승객 5명 척추 골절 |
| [Speed hump spine fractures (2011), J Spinal Disord Tech](https://read.qxmd.com/read/21150664/speed-hump-spine-fractures-injury-mechanism-and-case-series) | 46명, 버스 맨 뒷줄 42명 |
| [심재수 외 (2011), 한국도로학회논문집](https://db.koreascholar.com/Article/Detail/249899) | 수직 가속도는 방지턱 폭·높이 비에 좌우 |
| [임창식·최양원 (2016), 대한토목학회논문집](https://www.koreascience.or.kr/article/JAKO201608259723580.pdf) | 국내 회전교차로 고원식 횡단보도 높이 제안, Watts 인용 |

Π = v²/(g·R)가 같으면 크기가 달라도 원운동 가속도(g 단위)가 같으므로, 해석 가이드의 *실제 도로로 옮겨 보기*에서 사람 기준에 닿는 Π를 실제 방지턱 반경으로 환산합니다(서스펜션이 없는 모형이라 보수적인 추정).

## 출력 방식

- **라이브러리 PWM**: `picarx.forward(speed)`에 0~100을 그대로 전달합니다. 라이브러리가 내부에서 `speed/2 + 50`으로 바꾸므로 실제 듀티비는 약 50~100%이고, 출력 차이에 비해 속도 차이가 작습니다.
- **직접 듀티비**: `forward(1)`로 방향만 설정한 뒤 좌·우 뒷바퀴 PWM 핀(`motor_speed_pins`)에 듀티비를 직접 씁니다. 저속 구간까지 쓸 수 있어 속도 범위가 넓어집니다. 듀티가 너무 낮으면 모터가 출발하지 못하거나 방지턱 앞에서 멈출 수 있으니 10% 간격으로 내려가며 최저값을 찾으세요. 이 모드는 라이브러리의 모터 속도 보정값(`cali_speed_value`)을 적용하지 않습니다.

실험 출력 상한은 기본 100이며 `PICARX_EXPERIMENT_MAX_OUTPUT` 환경 변수로 낮출 수 있습니다. 수동 주행 화면의 PWM 상한(60)은 그대로입니다.

## 안전

- 자동 측정 주행은 0.1초마다 명령을 갱신하며, 주행 시간(최대 6 s)이 지나면 정지합니다. 서버 watchdog도 그대로 동작합니다.
- 주행 중 `/api/stop`(앱의 긴급 정지)을 누르면 즉시 멈추고, 그 시행은 *중단·제외* 상태로 저장됩니다.
- 주행로 끝에 벽이나 완충재를 두고, 주행 시간을 주행로 길이에 맞게 줄이세요.

## 데이터 파일

`backend/data/experiments/`(git 제외)에 시행마다 두 파일이 생깁니다.

- `<id>.json`: 조건, 방지턱 형상, 기록 정보, 분석 결과
- `<id>.csv`: 원자료 `t_s, ax_g, ay_g, az_g, gx_dps, gy_dps, gz_dps, vertical_g, dynamic_g`

설정은 `backend/data/experiment_settings.json`에 저장됩니다. 데이터 위치는 `PICARX_DATA_DIR`로 바꿀 수 있습니다.

## 라즈베리파이 업데이트와 접속 방법

화면을 HTTPS 주소로 열고 서버를 `http://<Pi-IP>:8000`으로 연결하면 브라우저가 요청·다운로드·카메라를 막습니다(콘솔의 *Mixed Content* 오류). 라즈베리파이가 화면도 제공하므로 **브라우저 주소창에 `http://<Pi-IP>:8000`을 직접 여는 것**이 가장 확실합니다.

```bash
# Raspberry Pi
cd ~/PiCarX-Control
git fetch && git checkout feature/mpu6050-impact-analysis && git pull
cd frontend && npm install && npm run build      # frontend/dist 생성 → FastAPI가 / 에서 제공
cd ../backend && sudo systemctl restart picarx-control   # 또는 uvicorn을 다시 실행
```

`sudo systemctl stop picarx-control`이 멈춘 것처럼 오래 걸리면, 열려 있는 카메라 영상 연결이 끝나기를 서버가 기다리는 것입니다. 한 번만 아래를 실행해 두면 최대 8초 안에 꺼집니다.

```bash
sudo mkdir -p /etc/systemd/system/picarx-control.service.d
printf '[Service]\nTimeoutStopSec=8\n' | sudo tee /etc/systemd/system/picarx-control.service.d/stop.conf
sudo systemctl daemon-reload
```

모터 점검 스크립트(`devtools/motor_test.py`, `motor_test2.py`)는 서버를 끈 뒤 `sudo` 없이 실행하세요. `sudo`로 실행하면 `/opt/picar-x/picar-x.conf`가 관리자 소유로 바뀌어 서버가 차량을 열지 못합니다(`Permission denied`). 그렇게 됐다면 `sudo chown -R $USER:$USER /opt/picar-x` 후 서버를 다시 켜세요.

실험 관리 화면에 *백엔드가 이전 버전* 안내가 보이면 Pi의 서버가 아직 예전 코드로 돌고 있는 것입니다(콘솔에 `/api/experiment/settings 404`). 위 명령으로 업데이트하고 재시작하세요. systemd 예시 파일은 `PICARX_MODE=mock`이므로 실제 주행에는 `hardware`로 바꿔야 합니다.

## 차량 없이 하드웨어 경로 시험

`backend/devtools/fake_hardware/`의 가짜 picarx·MPU-6050으로 센서 보정·측정·내보내기, 반복 측정, 직진 보정을 PC에서 시험할 수 있습니다. 사용법은 그 폴더의 README를 보세요.

## 라즈베리파이 준비

- I²C 속도를 400 kHz로 올리면 표본 속도가 좋아집니다. `/boot/firmware/config.txt`(구버전 `/boot/config.txt`)에 `dtparam=i2c_arm_baudrate=400000`을 추가하고 재부팅하세요.
- `smbus2`가 있으면 우선 사용하고, 없으면 `python3-smbus`를 사용합니다.
- 센서는 차체 중앙(앞·뒤 축 사이)에 나사나 핫글루로 단단히 고정합니다. 폼 양면테이프는 충격을 걸러냅니다. 센서를 뒤집어 붙여도 보정 시 중력 방향을 판별하므로 수직 가속도의 의미는 같습니다.
